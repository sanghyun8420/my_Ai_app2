## 저장소 배치와 기본 작업 순서

GitHub 저장소 루트의 `index.html`, `app.js` 등은 Pages 실행용으로 생성한 파일입니다. **수정 원본은 `source/` 안에 있습니다.** 전체 소스 ZIP을 풀었다면 ZIP 안의 프로젝트 루트가 같은 원본입니다.

```text
my_Ai_app2/
  index.html, app.js, ...       GitHub Pages 공개 파일
  AGENTS.md                    다음 AI 작업 안내
  CONTINUE.ko.md                바로 전달할 시작 문장
  source/
    dist/                      브라우저 소스
    worker/                    API 소스
    drizzle/                   D1 마이그레이션
    tests/                     회귀 검사
    scripts/                   검사·빌드·Pages 동기화
    .openai/hosting.json        기존 Sites 식별자와 바인딩
    package.json
    HANDOFF.ko.md
```

Node.js 24 LTS 권장, 최소 22.13입니다. `node:sqlite`가 API 테스트에 필요합니다. 프로젝트 루트에서:

```sh
npm install
npm test
npm run build
npm run dev
```

`@napi-rs/canvas`는 그림 테스트용 개발 의존성입니다. 설치 전에는 `npm run test:core`로 Node 기본 기능만 쓰는 검사를 실행할 수 있습니다. 게임 코드는 번들러나 프레임워크를 요구하지 않습니다.

`npm run dev`는 기본 `http://localhost:4173`에서 브라우저 파일과 기존 API 코드를 함께 실행합니다. 로컬 계정·친구·대전용 SQLite는 `.local/`에 생성되며 실제 서비스 DB와 별개입니다. 포트는 `PORT`로 지정합니다. `.local/`과 개인 DB는 커밋·코드 ZIP에 넣지 않습니다.

GitHub 체크아웃에서 `source/`를 수정하고 검사한 뒤, **저장소 루트**에서 다음 명령으로 공개 파일을 갱신합니다.

```sh
node source/scripts/sync-pages.mjs
```

변경 내용을 확인하고 커밋·푸시합니다. 현재 Pages는 `main` 브랜치의 `/(root)`를 배포합니다. 루트 실행 파일만 고치면 다음 생성 때 덮어써질 수 있으므로 원본도 함께 수정해야 합니다.

독립 소스 폴더에서 별도 내보내기를 하려면 비어 있는 출력 폴더를 사용합니다.

```sh
node scripts/export-github-pages.mjs /absolute/empty/output
```

## 실행 구조와 서버 배포

- `dist/index.html`과 모듈들은 원래 같은 출처의 `/api`를 사용합니다.
- Pages 내보내기는 `app.js`에 `remote-api.js` 연결을 주입해 기존 사이트 API를 호출하도록 만듭니다. 이 주입은 내보내기 스크립트에 맡깁니다.
- `npm run dev`는 같은 출처의 로컬 SQLite API를 제공하므로 별도 서비스 인증 없이 로컬 계정·친구·게임 기능을 개발할 수 있습니다. 실제 계정 데이터가 복사되지는 않습니다. 단순 정적 서버만 쓰면 게스트 게임은 실행되지만 로그인 API는 제공되지 않습니다. 공개 API의 CORS 정책을 로컬 편의를 위해 완화하지 않습니다.
- `worker/api.js`에는 로그인·친구·메시지·대전·순위가 있고 `scripts/build.mjs`는 브라우저 파일과 API를 한 Worker로 묶습니다.
- GitHub에 `source/worker`를 수정해 올리는 것만으로 **기존 Sites API가 교체되지는 않습니다.** 기존 Sites에 대한 배포 도구/권한이 있으면 같은 ID로 빌드 결과를 게시해야 합니다.
- 기존 서버에 접근할 수 없는 AI는 프론트엔드 개발을 계속하면서 현재 API 주소를 유지할 수 있습니다. 서버 변경이 꼭 필요하면 소유자가 별도 Cloudflare Worker/D1 권한과 바인딩을 연결한 뒤 마이그레이션·CORS·API 주소를 함께 변경해야 합니다.
- 계정·친구 데이터는 코드 ZIP에 없습니다. 기존 SQL을 지우거나 적용된 마이그레이션 번호를 재사용하지 않습니다.
- 독립 소스 ZIP에서 작업한다면 `node scripts/sync-pages.mjs /absolute/pages-root`처럼 공개 폴더를 명시합니다. `source-code.zip`과 `github-pages-download.html`은 재귀적으로 소스에 넣지 않습니다.

## 새 과학 모드

`science`는 수박정원의 모드 카드에서 바로 선택합니다. `science.js`가 정의와 그림, `physics.js`가 실제 충돌 반응을 처리합니다. 스킨 대신 재료별 과학 그림을 사용합니다.

| 단계 인덱스 | 물질/천체 |
|---|---|
| 0 | H 수소 원자 |
| 1 | O 산소 원자 |
| 2 | H₂ 수소 분자 |
| 3 | OH 중간 결합 |
| 4 | H₂O 물 분자 |
| 5~8 | 물방울 → 구름 → 성운 → 원시별 |
| 9~13 | 무거운 별 → 적색초거성 → 철핵 → 핵붕괴 → 초신성 |

화학 반응은 `H + H → H₂`, `H₂ + O → H₂O`, `H + O → OH`, `OH + H → H₂O`입니다. 어느 순서든 물 하나에 수소2개·산소1개가 정확히 쓰입니다. O+O나 잘못된 원자 조합은 합쳐지지 않습니다. 원자는 H:H:O 순환으로 공급합니다.

물 단계 이상은 같은 단계를 합쳐 다음 단계로 갑니다. **물 이후는 게임용 우주 테마 성장이고 실제 화학식이나 항성 진화의 재현은 아닙니다.** 마지막 초신성은 주변 물질 정리와 폭발 연출을 사용합니다. 단계는 기존 저장 스키마와 맞춘 0~13입니다.

모드를 추가할 때는 `physics`, `profile`, `save-state`, `preferences`, `social`, `worker/api`의 허용 목록과 앱 그림·다음 재료·반지름·기록 분기를 함께 확인합니다. 과학 단계 인덱스로 일반 과일 발견이나 수박 업적을 열지 않습니다.

## 경제와 저장: 보존이 특히 중요

`economy.js`의 `garden-economy-v1`이 현재 지갑과 다섯 게임 프로필의 권위 있는 저장입니다. 기존 다섯 개별 키는 이전용 백업이며, 공용 저장이 생긴 뒤 다시 합산하지 않습니다.

- 공용 보석: 스킨·배경·바구니·모자 꾸미기.
- 게임별 동전: 도구·부활·뽑기·강화·씨앗. 수박 부활10동전, 원정대 뽑기60/600동전, 장미/별빛 씨앗600/1400동전.
- 기존 잔액 합산과 삭제 도구·공룡 스킨 환급은 한 번만 처리합니다. 이미 산 스킨·장비는 유지합니다.
- 보석은 업적·첫 보스 보상과 누적 플레이로 획득합니다. 수박20과일·사과20칸·블록16칸·원정대20처치·정원1수확당5개입니다.
- 광산 스킨의 합치기 보너스는 수박 동전1/10개입니다.
- 구매·지급·영수증·게임 기록은 한 번의 공용 저장에 기록합니다. 저장 실패 시 구매 상태와 보석 델타를 함께 복구합니다.
- 같은 게임의 오래된 창은 기록 버전으로 거절하며, 임시 읽기 실패 후 기본값으로 기존 데이터를 덮어쓰지 않습니다.
- `suika-garden-run-v1`은 수박 판 저장, `suika-garden-preferences-v1`은 설정입니다. 이 키와 게임별 기존 키를 이유 없이 변경하지 않습니다.

지갑·게임판·소유권은 **기기·브라우저·사이트 출처별 저장**입니다. 기기 저장은 계속 유지하며, 닉네임 참여 후에는 서버 백업과 복구 코드로 다른 주소·기기에 이전할 수 있습니다. 이름만으로 기존 사용자를 조회하거나 기록 소유권을 복원하지 않습니다. 서버 권위 경제·현금 결제·부정행위 방지는 구현되어 있지 않습니다.

## 이름만으로 순위 참여와 서버 복구

- `dist/player-cloud.js`가 선택형 닉네임 입력, 이전 최고점수 등록, 서버 백업, 복구 코드를 관리합니다. 첫 방문에 이름·회원가입 창을 자동으로 열지 않습니다. 상단 로그인과 설정의 가입 보상에서 정식 계정을 만들며, 선택형 닉네임·복구 기능은 내 기록 메뉴에 남아 있습니다.
- `/api/guest`는 비밀번호 없이 내부 플레이어를 만듭니다. 기기에서 생성한32바이트 무작위 키를 서버에는 SHA-256 해시로만 저장합니다. `garden-player-v1`의 키 원문은 비밀 인증 수단이며 URL·순위·코드 ZIP·진행 스냅샷에 넣지 않습니다. 동일 닉네임도 별도 플레이어입니다.
- `drizzle/0004_nickname_cloud.sql`이 키와 백업 테이블을 추가합니다. 기존 계정·친구·순위 테이블과 정상 로그인은 유지합니다. 서버를 먼저 배포한 뒤 새 Pages 클라이언트를 배포합니다.
- `/api/profile/import`는 기기에 남은 수박·사과·블록의 기본 최고점수를 단조 증가로 등록합니다. 특수 모드 기록을 기본 순위에 섞지 않습니다. 두 사이트 모두 같은 API의 순위를 읽습니다.
- `garden-economy-v1`과 허용된 게임판·설정 키만 서버에 저장하며 세션·복구 키는 제외합니다. 약20초마다 변경을 저장하고 탭을 숨길 때도 저장을 시도합니다. 오프라인에서는 기기 저장으로 플레이합니다.
- `/api/cloud-save`는 인증된 플레이어의 스냅샷만 읽고 씁니다. 버전 비교로 오래된 창의 덮어쓰기를 거절합니다. 새 주소·기기의 기록과 충돌하면 서버 불러오기 또는 기기 기록으로 저장하기를 직접 고르도록 합니다.
- 복구는 기존 키를 한 번 입력해 같은 플레이어로 접속한 뒤 서버 기록을 불러옵니다. 교체 전 기기 기록을 백업하고 검증된 스냅샷을 `garden-cloud-pending-v1`에 예약합니다. 새 페이지가 모델을 만들기 전에 적용하므로 기존 페이지의 종료 저장이 복구한 지갑을 덮어쓰지 않습니다. 보석 잔액을 합산하지 않고 전체 스냅샷을 복원합니다.
- `garden-cloud-meta-v1`에는 서버 버전·플레이어 ID·변경 감지용 해시만 있습니다. 기기 키를 지우거나 복구 코드를 잃으면 닉네임만으로 다른 기기의 기록을 복구할 수 없습니다. 기존 계정 사용자는 기존 아이디·비밀번호로 로그인할 수 있습니다.
- 현재 순위는 클라이언트가 제출하는 최고점수이며 경쟁 게임 수준의 치트 방지는 별도 작업입니다.

## 홈 화면 설치와 오프라인 게임

- `dist/install.js`는 실제 플레이35초 후 설치 안내를 한 번 표시합니다. 다른 창이 열렸거나 탭이 숨겨져 있으면 시간을 세지 않습니다. 설치 창은 수박·퍼즐·원정대의 진행을 멈추고 닫을 때 이어갑니다.
- 닫으면 `garden-install-v1`에7일 대기 상태를 기록합니다. 이미 설치했거나 standalone으로 실행 중이면 자동 안내를 생략합니다. 메뉴의 ‘홈 화면에 추가’는 언제든 열 수 있습니다.
- Chromium의 `beforeinstallprompt`를 보관하고 사용자가 버튼을 누른 순간 실제 `prompt()`를 호출합니다. 설치 완료 표시는 실제 `appinstalled` 이벤트를 기준으로 합니다. iOS와 지원하지 않는 브라우저에는 수동 추가 절차를 안내합니다. 웹 코드가 운영체제 설치를 강제로 실행하지 않습니다.
- `dist/manifest.webmanifest`의 `id`, `start_url`, `scope`는 모두 상대 주소 `./`입니다. 기존 주소·프로젝트 경로에서 열어야 기기의 같은 저장소를 사용할 수 있으므로 별도 설치용 사이트로 보내지 않습니다. 이름·로그인 없이도 기기 자동 저장은 작동하며 브라우저 데이터를 삭제하면 기기 기록도 삭제될 수 있습니다.
- `scripts/create-app-icons.mjs`가 기존 게임의 수박 그림으로192·512·maskable512·Apple180 아이콘을 생성합니다. 그림을 바꿀 때만 실행합니다. PNG는 저장소에 포함됩니다.
- `scripts/pwa-assets.mjs`는 게임 자산과 생성기 코드의 해시로 `dist/sw.js`를 생성합니다. 빌드와 Pages 내보내기가 각각 실행하며, Pages에서는 주입된 `remote-api.js`도 오프라인 캐시에 포함합니다.
- 서비스워커는 같은 출처·앱 경로의 정적 게임 파일만 설치 시 캐시합니다. 온라인에서는 최신 서버 응답을 사용하고 연결이 끊기면 게임 파일을 제공합니다. API·계정 세션·순위·서버 백업·소스 ZIP·다운로드 HTML은 캐시하지 않습니다. 다른 앱의 캐시나 기기 저장을 삭제하지 않습니다.
- 실행 중인 게임을 강제로 새로고침하거나 `skipWaiting`으로 업데이트하지 않습니다. 오프라인에는 기기에 저장하며 친구·순위·서버 저장은 연결이 필요합니다. 실제 OS의 설치 UI와 iOS 저장소 분리 여부는 해당 기기에서 추가 확인이 필요합니다.

## 선택형 회원가입과 보석500 보상

- 첫 방문에는 바로 게스트 게임을 플레이합니다. 상단 ‘로그인’으로 팝업을 열고 하단 ‘계정이 없으신가요? 회원가입’으로 전환합니다. 설정은 미가입 플레이어에게 ‘회원가입하면 보석500개’를 표시합니다. 기기 저장은 로그인 없이도 유지합니다.
- 새 아이디는 영문과 숫자를 모두 넣어4~20자이며 중복은 대소문자 구분 없이 거절합니다. `/api/auth/availability`의 실제 중복 조회와 가입 시 고유 제약을 함께 사용합니다. 기존 밑줄 포함 아이디 등은 로그인할 수 있습니다.
- 비밀번호는8~128자, 영문·숫자 필수이며 대소문자를 구분해 해시합니다. 대문자와 소문자를 반드시 둘 다 넣으라는 뜻은 아닙니다. `passwordConfirm`은 원문과 정확히 같아야 합니다. 화면과 서버에서 모두 검사합니다.
- `drizzle/0005_signup_rewards.sql`은 가입 보상 영수증을 계정별 하나만 기록합니다. 회원가입 API는 정식 계정 생성 또는 기존 guest 계정 전환, 보석500을 더한 서버 스냅샷, 영수증, guest 키·세션 폐기를 한 트랜잭션으로 처리합니다. 친구 코드·계정 ID·순위·친구 관계는 전환 시 그대로 유지합니다.
- 가입 요청에는 현재 게임 스냅샷과 서버 버전이 포함됩니다. 비밀번호 해시를 만드는 동안 다른 기기가 저장해도 SQL CHECK가 전체 변경을 되돌립니다. 성공 응답의 스냅샷을 초기화 전 복원하여 현재 보석·스킨·게임판과 보상500을 함께 보존합니다. 다시 로그인하거나 요청을 재전송해도 같은 계정에 보상을 더 주지 않습니다.
- `economy.js`의 `rewardRules:2`는 더 쉬운 보석 기준입니다. 기존 기록은 새 기준으로 기준점만 옮겨 이전 진행에 보상을 재지급하지 않으며, 이후 새 진행마다5개를 줍니다. 과거 잔액·가입 영수증·소유권은 보존합니다.
- Google·Apple 앱 등록 정보가 현재 제공되지 않아 소셜 로그인 버튼을 표시하지 않습니다. 지원하는 것처럼 보이는 가짜 로그인 UI를 추가하지 않습니다.
- 쫄라맨은 고정된 앉은 자세이며 클릭해도 이동·낙하·효과음 없이 말풍선만 표시합니다.
