## 저장소 배치와 기본 작업 순서

GitHub 저장소 루트의 `index.html`, `app.js` 등은 Pages 실행용으로 생성한 파일입니다. **수정 원본은 `source/` 안에 있습니다.** 전체 소스 ZIP을 풀었다면 ZIP 안의 프로젝트 루트가 같은 원본입니다.

```text
my_Ai_app2/
  index.html, app.js, ...       GitHub Pages 공개 파일
  AGENTS.md                    다음 AI 작업 안내
  CONTINUE.ko.md                바로 전달할 시작 문장
  source/
    dist/                      브라우저 소스
    worker/                    API 소스
    drizzle/                   D1 마이그레이션
    tests/                     회귀 검사
    scripts/                   검사·빌드·Pages 동기화
    .openai/hosting.json        기존 Sites 식별자와 바인딩
    package.json
    HANDOFF.ko.md
```

Node.js 24 LTS 권장, 최소 22.13입니다. `node:sqlite`가 API 테스트에 필요합니다. 프로젝트 루트에서:

```sh
npm install
npm test
npm run build
npm run dev
```

`@napi-rs/canvas`는 그림 테스트용 개발 의존성입니다. 설치 전에는 `npm run test:core`로 Node 기본 기능만 쓰는 검사를 실행할 수 있습니다. 게임 코드는 번들러나 프레임워크를 요구하지 않습니다.

`npm run dev`는 기본 `http://localhost:4173`에서 브라우저 파일과 기존 API 코드를 함께 실행합니다. 로컬 계정·친구·대전용 SQLite는 `.local/`에 생성되며 실제 서비스 DB와 별개입니다. 포트는 `PORT`로 지정합니다. `.local/`과 개인 DB는 커밋·코드 ZIP에 넣지 않습니다.

GitHub 체크아웃에서 `source/`를 수정하고 검사한 뒤, **저장소 루트**에서 다음 명령으로 공개 파일을 갱신합니다.

```sh
node source/scripts/sync-pages.mjs
```

변경 내용을 확인하고 커밋·푸시합니다. 현재 Pages는 `main` 브랜치의 `/(root)`를 배포합니다. 루트 실행 파일만 고치면 다음 생성 때 덮어써질 수 있으므로 원본도 함께 수정해야 합니다.

독립 소스 폴더에서 별도 내보내기를 하려면 비어 있는 출력 폴더를 사용합니다.

```sh
node scripts/export-github-pages.mjs /absolute/empty/output
```

## 실행 구조와 서버 배포

- `dist/index.html`과 모듈들은 원래 같은 출처의 `/api`를 사용합니다.
- Pages 내보내기는 `app.js`에 `remote-api.js` 연결을 주입해 기존 사이트 API를 호출하도록 만듭니다. 이 주입은 내보내기 스크립트에 맡깁니다.
- `npm run dev`는 같은 출처의 로컬 SQLite API를 제공하므로 별도 서비스 인증 없이 로컬 계정·친구·게임 기능을 개발할 수 있습니다. 실제 계정 데이터가 복사되지는 않습니다. 단순 정적 서버만 쓰면 게스트 게임은 실행되지만 로그인 API는 제공되지 않습니다. 공개 API의 CORS 정책을 로컬 편의를 위해 완화하지 않습니다.
- `worker/api.js`에는 로그인·친구·메시지·대전·순위가 있고 `scripts/build.mjs`는 브라우저 파일과 API를 한 Worker로 묶습니다.
- GitHub에 `source/worker`를 수정해 올리는 것만으로 **기존 Sites API가 교체되지는 않습니다.** 기존 Sites에 대한 배포 도구/권한이 있으면 같은 ID로 빌드 결과를 게시해야 합니다.
- 기존 서버에 접근할 수 없는 AI는 프론트엔드 개발을 계속하면서 현재 API 주소를 유지할 수 있습니다. 서버 변경이 꼭 필요하면 소유자가 별도 Cloudflare Worker/D1 권한과 바인딩을 연결한 뒤 마이그레이션·CORS·API 주소를 함께 변경해야 합니다.
- 계정·친구 데이터는 코드 ZIP에 없습니다. 기존 SQL을 지우거나 적용된 마이그레이션 번호를 재사용하지 않습니다.
- 독립 소스 ZIP에서 작업한다면 `node scripts/sync-pages.mjs /absolute/pages-root`처럼 공개 폴더를 명시합니다. `source-code.zip`과 `github-pages-download.html`은 재귀적으로 소스에 넣지 않습니다.

## 새 과학 모드

`science`는 수박정원의 모드 카드에서 바로 선택합니다. `science.js`가 정의와 그림, `physics.js`가 실제 충돌 반응을 처리합니다. 스킨 대신 재료별 과학 그림을 사용합니다.

| 단계 인덱스 | 물질/천체 |
|---|---|
| 0 | H 수소 원자 |
| 1 | O 산소 원자 |
| 2 | H₂ 수소 분자 |
| 3 | OH 중간 결합 |
| 4 | H₂O 물 분자 |
| 5~8 | 물방울 → 구름 → 성운 → 원시별 |
| 9~13 | 무거운 별 → 적색초거성 → 철핵 → 핵붕괴 → 초신성 |

화학 반응은 `H + H → H₂`, `H₂ + O → H₂O`, `H + O → OH`, `OH + H → H₂O`입니다. 어느 순서든 물 하나에 수소2개·산소1개가 정확히 쓰입니다. O+O나 잘못된 원자 조합은 합쳐지지 않습니다. 원자는 H:H:O 순환으로 공급합니다.

물 단계 이상은 같은 단계를 합쳐 다음 단계로 갑니다. **물 이후는 게임용 우주 테마 성장이고 실제 화학식이나 항성 진화의 재현은 아닙니다.** 마지막 초신성은 주변 물질 정리와 폭발 연출을 사용합니다. 단계는 기존 저장 스키마와 맞춘 0~13입니다.

모드를 추가할 때는 `physics`, `profile`, `save-state`, `preferences`, `social`, `worker/api`의 허용 목록과 앱 그림·다음 재료·반지름·기록 분기를 함께 확인합니다. 과학 단계 인덱스로 일반 과일 발견이나 수박 업적을 열지 않습니다.

## 경제와 저장: 보존이 특히 중요

`economy.js`의 `garden-economy-v1`이 현재 지갑과 다섯 게임 프로필의 권위 있는 저장입니다. 기존 다섯 개별 키는 이전용 백업이며, 공용 저장이 생긴 뒤 다시 합산하지 않습니다.

- 공용 보석: 스킨·배경·바구니·모자 꾸미기.
- 게임별 동전: 도구·부활·뽑기·강화·씨앗. 수박 부활은 한 판에서10→100→1,000…동전(매번10배), 원정대 뽑기60/600동전, 장미/별빛 씨앗600/1400동전.
- 기존 잔액 합산과 삭제 도구·공룡 스킨 환급은 한 번만 처리합니다. 이미 산 스킨·장비는 유지합니다.
- 보석은 업적·첫 보스 보상과 누적 플레이로 획득합니다. 수박20과일·사과20칸·블록16칸·원정대20처치·정원1수확당5개입니다.
- 광산 스킨의 합치기 보너스는 수박 동전1/10개입니다.
- 구매·지급·영수증·게임 기록은 한 번의 공용 저장에 기록합니다. 저장 실패 시 구매 상태와 보석 델타를 함께 복구합니다.
- 같은 게임의 오래된 창은 기록 버전으로 거절하며, 임시 읽기 실패 후 기본값으로 기존 데이터를 덮어쓰지 않습니다.
- `suika-garden-run-v1`은 수박 판 저장, `suika-garden-preferences-v1`은 설정입니다. 이 키와 게임별 기존 키를 이유 없이 변경하지 않습니다.

지갑·게임판·소유권은 **기기·브라우저·사이트 출처별 저장**입니다. 기기 저장은 계속 유지하며, 자동 게스트부터 서버 저장하며 같은 계정 로그인 또는 게스트 복구 코드로 다른 주소·기기에 연결할 수 있습니다. 이름만으로 기존 사용자를 조회하거나 기록 소유권을 복원하지 않습니다. 서버 권위 경제·현금 결제·부정행위 방지는 구현되어 있지 않습니다.

## 이름만으로 순위 참여와 서버 복구

- `dist/player-cloud.js`가 선택형 닉네임 입력, 이전 최고점수 등록, 서버 백업, 복구 코드를 관리합니다. 첫 방문에 이름·회원가입 창을 자동으로 열지 않습니다. 상단 로그인과 설정의 가입 보상에서 정식 계정을 만들며, 선택형 닉네임·복구 기능은 내 기록 메뉴에 남아 있습니다.
- `/api/guest`는 비밀번호 없이 내부 플레이어를 만듭니다. 기기에서 생성한32바이트 무작위 키를 서버에는 SHA-256 해시로만 저장합니다. `garden-player-v1`의 키 원문은 비밀 인증 수단이며 URL·순위·코드 ZIP·진행 스냅샷에 넣지 않습니다. 동일 닉네임도 별도 플레이어입니다.
- `drizzle/0004_nickname_cloud.sql`이 키와 백업 테이블을 추가합니다. 기존 계정·친구·순위 테이블과 정상 로그인은 유지합니다. 서버를 먼저 배포한 뒤 새 Pages 클라이언트를 배포합니다.
- `/api/profile/import`는 기기에 남은 수박·사과·블록의 기본 최고점수를 단조 증가로 등록합니다. 특수 모드 기록을 기본 순위에 섞지 않습니다. 두 사이트 모두 같은 API의 순위를 읽습니다.
- `garden-economy-v1`과 허용된 게임판·설정 키만 서버에 저장하며 세션·복구 키는 제외합니다. 약5초마다 변경을 저장하고 지갑 변경은1.8초 뒤 저장하며 탭을 숨기거나 나갈 때도 keepalive 크기 한도 내에서 저장을 시도합니다. 오프라인에서는 기기 저장으로 플레이합니다.
- `/api/cloud-save`는 인증된 플레이어의 스냅샷만 읽고 씁니다. 버전 비교로 오래된 창의 덮어쓰기를 거절합니다. 새 주소·기기에서는 같은 계정 로그인 또는 게스트 복구로 연결하면 최신 서버 기록을 자동으로 불러옵니다. CAS 충돌도 최신 서버 스냅샷을 자동으로 적용하고 교체 전 기기 백업을 남깁니다. 명시적인 고급 복구 메뉴에서만 수동 덮어쓰기를 제공합니다.
- 복구는 기존 키를 한 번 입력해 같은 플레이어로 접속한 뒤 서버 기록을 불러옵니다. 교체 전 기기 기록을 백업하고 검증된 스냅샷을 `garden-cloud-pending-v1`에 예약합니다. 새 페이지가 모델을 만들기 전에 적용하므로 기존 페이지의 종료 저장이 복구한 지갑을 덮어쓰지 않습니다. 보석 잔액을 합산하지 않고 전체 스냅샷을 복원합니다.
- `garden-cloud-meta-v1`에는 서버 버전·플레이어 ID·계정 유형·변경 감지용 해시와 응답 대기 중인 저장의 버전·해시가 있습니다. 응답이 유실된 자신의 저장을 인식해 더 새로운 기기 기록을 잘못 되돌리지 않습니다. 정기 변경 감지에서는 지갑 revision/recordVersions와 게임판 savedAt만 제외합니다. 첫 방문은 자동 게스트이며 정식 계정의 세션 만료를 새 게스트로 바꾸지 않습니다. 로그아웃은 인증 메타데이터만 정리하고 게임 기록을 남깁니다. 기기 키를 지우거나 복구 코드를 잃으면 닉네임만으로 다른 기기의 기록을 복구할 수 없습니다. 기존 계정 사용자는 기존 아이디·비밀번호로 로그인할 수 있습니다.
- 현재 순위는 클라이언트가 제출하는 최고점수이며 경쟁 게임 수준의 치트 방지는 별도 작업입니다.

## 홈 화면 설치와 오프라인 게임

- `dist/install.js`는 실제 플레이35초 후 설치 안내를 한 번 표시합니다. 다른 창이 열렸거나 탭이 숨겨져 있으면 시간을 세지 않습니다. 설치 창은 수박·퍼즐·원정대의 진행을 멈추고 닫을 때 이어갑니다.
- 닫으면 `garden-install-v1`에7일 대기 상태를 기록합니다. 이미 설치했거나 standalone으로 실행 중이면 자동 안내를 생략합니다. 메뉴의 ‘홈 화면에 추가’는 언제든 열 수 있습니다.

- 특별 배는 일반 배와 같은5단계이며 `body.special` 플래그와 금빛 반짝임으로 구분합니다. `PEAR_LEVEL`은5이고 특별 사과의 기존 도구 보상은 유지합니다. 일반 플레이에서4번째부터5번마다 특별 배를 예고하며, 합쳐서 만들어지는 배도40% 확률로 특별 배입니다. 사과·수박 전용 드롭과 과학 모드에는 배 드롭을 끼워 넣지 않습니다.

## 로그인 유지 수정

- 기존 Sites 원본에서 로그인 POST는200이지만 뒤의 cloud-save GET이401인 문제를 실제 운영 로그로 확인했습니다. `dist/api-session.js`가 앱 인증을 보존하고, GardenSocial의 기본 fetcher에 적용합니다. 쿠키 전달이 실패해도 인증된 게임 요청을 보낼 수 있습니다.
- 동일 출처의 인증 POST에는 `X-Garden-Session: bearer`를 명시하고 API가 세션 토큰을 응답합니다. 외부 Pages 인증은 기존과 같이 토큰을 응답하며 쿠키를 보내지 않습니다. 일반 me·cloud-save 응답에는 인증 토큰이 없습니다. 세션 원문은 게임 저장·복구 ZIP·URL에 포함하지 않습니다.
- API 세션 저장 키는 기존 `suika-garden-api-session-v1:<API 원본>`을 유지합니다. 기억 설정이 false면 탭 저장, 기본은 기기 저장이며 로그아웃하면 지웁니다. 세션은 기존30일 만료를 따릅니다.
- 두 주소의 클라이언트가 같은 세션 모듈을 사용합니다. 편집 원본의 Pages 어댑터는 ../../dist/api-session.js를 가져오고 내보내기에서 ./api-session.js로 바꿉니다. 늦은401·늦은 게스트 인증 응답과 초기 me 응답은 새 계정을 덮어쓰지 않습니다.
- `tests/auth-persistence.mjs`는 모든 쿠키를 버리는 전송으로 실제 API와 지갑을 사용해 가입→복원→재접속과 다른 기기 로그인을 검사합니다. 이전 쿠키 전용 테스트도 유지합니다. 운영 사용자 계정이나 기록을 테스트용으로 수정하지 않습니다.

## 동물원 모드·상단 메뉴·계정 자동 순위

- `dist/zoo.js`가15개 ZOO_STAGES와 Canvas 동물 그림을 제공합니다. 물리·저장·프로필·설정·소셜·방 API의 모드 허용 목록에 zoo를 포함합니다. stage 인덱스0~14는 zoo에만 허용하고 기존 과일은0~13입니다. 각 동물의 반경과 점수를 물리 엔진이 실제로 사용하며 마지막 고래끼리는16단계로 합쳐지지 않습니다.
- 동물원은 특별 사과/배·기본 과일 발견·수박 업적을 해제하지 않습니다. 동물원 best는 modeBestScores.zoo입니다. generic동전·합치기 진행은 유지합니다. 다른 특수 모드처럼 나가기·재접속 뒤에는 기본 수박게임으로 돌아옵니다. 동물원 저장은14번 인덱스·고래 표시를 읽어 정산한 뒤 기본 모드로 돌아올 수 있어야 합니다.
- 상단 discovery-nav에는 games-open/modes-header-open/shop-open/ranking-open 네 진입점이 있습니다. 기존 로고 선택 기능도 유지합니다. header 높이는 ResizeObserver가 실제 측정하며 작은 세로 화면에서는 점수·도구 여백을 줄입니다. 성장 게임에서는 모드/순위 버튼 글자를 난이도·품종/기록으로 바꿉니다.
- 리더보드는 가입 계정을0점부터 자동 포함합니다. 자동 게스트0점만 제외하고 기존 양수 게스트 기록은 유지합니다. garden_game_scores, 계정 best_score, 최신 cloud-save의 canonical 지갑·예전 기기 백업 최고점수 중 최댓값을 읽습니다. 예전 backup JSON은 json_valid를 확인하여 손상된 문자열이 전체 순위를 깨지 않도록 합니다.
- 공개 응답의 scores는 최대50명이며 rank를 포함합니다. 유효한 세션이면 me에50위 밖의 본인 순위도 제공합니다. 프런트에서 수동 점수 업로드가 성공해야만 순위를 볼 수 있는 의존 관계를 제거했습니다. 순위에는 기본 게임 점수만 사용하고 zoo/science 등 특수 모드 기록은 섞지 않습니다.
- tests/zoo.mjs는14번 합치기 전이·15단계 저장·모드 격리, automatic-leaderboard.mjs는 계정 자동0점 참여·51명 이상의 순위·서버 백업 점수·이전 백업 손상·zoo 방을 검사합니다. skin-art는15개 동물 그림과 그리기 상태도 확인합니다.


## 최고기록 동기화 보완 및 제거 항목

`PlayerCloud.load`는 같은 소유자의 로컬 기본 최고점수와 모드별 최고점수만 최댓값으로 병합합니다. 명시적 기존 계정 로그인은 게스트/소유자 미지정 기록의 점수만 가져올 수 있으며, 알려진 다른 회원의 기록은 가져오지 않습니다. 지갑·구매·진행 중 보드는 서버 값을 사용합니다. 복원 메타의 hash는 원래 서버 스냅샷 hash여야 복원 뒤 더 높은 기록을 재업로드합니다. 소유자 정보 없는 옛 기기 백업을 임의 계정에 자동 적용하지 않습니다.

`leaderboard-live.js`는 열린 리더보드만5초마다 갱신하고 게임/계정/닫기 이후 오래된 응답을 버립니다. 기본 순위에 특수 모드 점수를 넣지 않습니다.

크리스탈(`gem`,60보석)은 카탈로그에서 제거됐습니다. 프로필 초기화에서 소유권 제거와60보석 환급, `removedCrystalV45` 이전 표시를 한 번에 저장합니다. 보석 광산(`royalGem`)은 별개로 유지합니다. 사과 키우기 UI는 제거됐지만 기존 다섯 레코드 구조/공용 지갑/레거시 모델은 저장 호환성을 위해 유지합니다.


이어하기 비용은 `profile.js`의 `getRevivalCost()`를 UI와 구매 검증에서 함께 사용합니다. `activeRun.revivalCount`를 성공한 결제와 원자적으로 저장하고 새 판에는0으로 초기화합니다. 이전 저장의 카운터가 없으면 같은 판의 부활 영수증으로 보완합니다. 가격이10인 예전 영수증과 새 가격의 복구 스냅샷을 모두 읽으며, 중복 결제·저장 실패 시 횟수와 지갑을 되돌립니다.
친구 추가의 초대 링크 생성 UI는 제거했습니다. 기존 링크 수락 호환 API는 남기고, 대전방 공유의 수동 복사는 대전 탭의 `room-share-link` 입력칸을 사용합니다.
