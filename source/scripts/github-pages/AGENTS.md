# 수박정원 저장소 작업 안내

이 저장소는 이미 공개 중인 수박정원 게임입니다. 현재 상태에서 이어서 개발합니다.

- 먼저 `source/HANDOFF.ko.md`와 `CONTINUE.ko.md`를 읽습니다.
- 수정 원본은 `source/`입니다. 루트의 실행용 HTML/JS만 따로 고치지 않습니다.
- 브라우저 소스는 `source/dist/`, API는 `source/worker/`, 데이터베이스 마이그레이션은 `source/drizzle/`입니다.
- Node.js 24 LTS 권장(최소22.13). `source/`에서 `npm install`, `npm test`, `npm run build`를 실행합니다. `npm run dev`는 localhost:4173의 로컬 게임/API를 실행하고 `.local/`에 별도 SQLite를 만듭니다.
- 저장소 루트에서 `node source/scripts/sync-pages.mjs`로 공개 파일을 갱신하고 생성된 변경도 함께 검토·커밋합니다.
- GitHub Pages는 `main`의 `/(root)`를 배포합니다. 기존 Sites API 배포는 별도 권한/도구가 필요합니다. GitHub 푸시만으로 서버 코드가 바뀌었다고 안내하지 않습니다.
- 현재 API 주소와 Sites 식별자를 임의로 바꾸거나 새 사이트를 만들지 않습니다.
- `garden-economy-v1`과 레거시 이전 영수증·소유권·게임 기록을 보존합니다. 개별 보석 잔액을 다시 합산하거나 데이터 초기화로 오류를 숨기지 않습니다.
- 사과모아는 나가면 새 판, 블록과 기본 수박은 이어하기, 수박 특수 모드는 나가기/재접속 후 기본 게임 복귀를 유지합니다.
- 과학 모드의 원자 반응은 실제로2H+O를 소비해야 합니다. 물 이후는 게임 테마 성장임을 구분합니다.
- 닉네임 플레이의 복구 키는 비밀 인증 수단입니다. 이름만으로 소유권을 복원하지 않고 서버 백업의 버전 충돌·복원 전 기기 백업·페이지 초기화 전 적용을 유지합니다.
- 설치용 manifest의 상대 scope/start_url과 정적 자산 전용 서비스워커를 유지합니다. API·인증·서버 저장은 캐시하지 않고 실행 중인 게임을 강제로 새로고침하지 않습니다.
- 가입500 보상은 서버 영수증·지갑 스냅샷·guest 전환을 원자적으로 처리합니다. 클라이언트에서 중복 지급하거나 가입 충돌을 무시하지 않습니다. 새 보석 기준의 기존 진행 기준점 이전을 유지합니다.
- 특별 배는 실제 제거한 개수만 세고3개마다 보석1~5개를 한 번 지급합니다. 판별/프로필 누적 기록과 구버전0 기본값, 부활·복구의 중복 방지를 유지합니다.
- 비밀번호·토큰·인증 쿠키·개인 DB를 코드나 응답에 넣지 않습니다. 연결된 도구의 정상 인증 방식을 사용합니다.
- 검증한 내용과 실제 브라우저/기기에서 확인하지 못한 내용을 구분해 알립니다.

- 최신 기본 흐름은 자동 게스트·5초 서버 저장·동일 계정 로그인 시 최신 기록 자동 복원입니다. CAS 충돌 시 기기 백업 후 최신 서버 기록을 적용합니다. MAX 카운트다운5초·흔들기 보호·중단 중 타이머 정지·재접속 시 남은 시간 유지 규칙을 보존합니다.

- zoo는15단계(인덱스0~14)이며 기존 과일은0~13입니다. 동물원 점수는 별도 저장하고 기본 과일 발견·업적에 섞지 않습니다. 상단 네 글자 메뉴와 가입 계정의 자동 순위 참여·본인 전체 순위 표시를 유지합니다.

- 크리스탈(`gem`)과 사과 키우기는 제거됐습니다. 스피드 정원 레이싱을 포함해 다섯 게임을 선택·실행하며 예전 재배 저장 키는 호환용으로 보존합니다. 크리스탈60보석 환급은 `removedCrystalV45`로 한 번 처리합니다.
- 서버 복원 시 같은 계정의 더 높은 기본/모드별 최고점수만 보존하고 지갑은 합산하지 않습니다. 복원 메타 hash는 원본 서버 값을 유지해 병합된 최고기록을 재업로드합니다. 리더보드의5초 갱신/오래된 응답 차단을 유지합니다.

- racing은 `racing-model.js`/`racing-art.js`/`racing.js`/`racing.css`로 구성합니다. 기존 GAME_KEYS는 다섯 레거시 키로 유지하고, 새 레이싱 레코드 RACING_KEY는 canonical records 안에 선택적으로 저장합니다. 주행/차고는 서버 백업에 함께 들어가며 보상 run ID 중복 방지·실패 롤백·60Hz 고정 간격·메뉴/숨김/포인터 취소 입력 해제를 유지합니다.
